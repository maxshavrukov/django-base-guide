README — проект BASE GUIDE / Django shop
============================================
Небольшой интрнет магазин с рабочей админ панелью.
Главный принцип архитектуры такой:

+--> main/               <- каталог, товары, поиск, общий шаблон
+--> basket/             <- корзина
+--> orders/             <- оформление заказа
+--> users/              <- авторизация, профиль, бонусы
+--> wishlist/           <- избранное

Главный HTML-шаблон находится здесь:
    main/templates/main/base.html

Большинство публичных страниц наследуются от него через обычный Django `{% extends 'main/base.html' %}`.
Поэтому, если нужно поменять шапку, каталог, поиск, мини-корзину, подключение глобального CSS
или общий JavaScript — в первую очередь смотреть base.html и main/static/style.css.

------------------------------------------------------------
1. КАК УСТРОЕН ПРОЕКТ
------------------------------------------------------------

shop/
    Django-конфигурация всего проекта: settings, корневые URL, ASGI/WSGI.

main/
    Главное приложение магазина.
    Здесь находятся модели товаров/категорий/брендов/акций/баннеров,
    каталог, фильтры, сортировка, поиск, карточки товара и общий шаблон.
    Товары тут наследуются под классом. Есть главный с общими характеристиками
    и уже сами товары с своими характеристиками.
    * при добавлении новой категории товара - нужно создать модель + миграции!

basket/
    Работа корзины. Для гостя корзина хранится в session,
    для авторизованного пользователя — в таблице BasketItem.

orders/
    Создание заказа из корзины и сохранение состава заказа.
    Здесь же находится сигнал, который после установки paid=True
    запускает начисление бонусов за покупку.

users/
    Профиль пользователя, авторизация, история заказов,
    недавно просмотренные товары и вся бонусная система.

wishlist/
    Избранное. Для гостя — session, для авторизованного — база данных.

media/
    Загружаемые файлы: изображения товаров, логотипы брендов, баннеры.

products/
    Старые/загруженные изображения товаров, которые лежат вне app static/media.

main/fixtures/catalog_dump.json
    Снимок каталога для переноса/восстановления каталожных данных.

db.sqlite3
    Локальная SQLite база проекта. В Git она исключена через .gitignore.

requirements.txt
    Зависимости Python.

instruction.txt
    Короткая инструкция по обновлению каталога на Render.

2. ГЛАВНЫЙ ПОТОК СТРАНИЦЫ
------------------------------------------------------------

Для обычной страницы путь примерно такой:

URL -> shop/urls.py -> app/urls.py -> views.py -> service -> template -> browser

Например, каталог:
    / 
      -> shop/urls.py подключает main.urls
      -> main/urls.py вызывает main.views.product_list
      -> product_list вызывает сервисы main/services/*
      -> передаёт данные в main/product/list.html
      -> list.html наследует main/base.html
      -> браузер получает итоговый HTML

Для страницы товара:
    /123/iphone-...
      -> main.views.product_detail
      -> main.services.product_detail
      -> main/templates/main/product/detail.html

Для корзины:
    POST /basket/add/123/
      -> basket.views.basket_add
      -> basket.services.basket.Basket.add
      -> ответ JSON для AJAX или redirect

3. КАК РАЗБИРАТЬСЯ, ЕСЛИ ЗАБЫЛ КОД
------------------------------------------------------------

1) Сначала найди URL в app/urls.py.
2) Из URL перейди в views.py.
3) Посмотри, какой service вызывается из view.
4) Посмотри, какая модель участвует в запросах к БД.
5) Посмотри template, который рендерится.
6) Для внешнего вида ищи классы из template в static/*.css.
7) Для интерактивности ищи JavaScript из base.html или block extra_js.

Очень полезное правило проекта:

    views.py = «какую страницу вернуть»
    services/ = «как получить/посчитать данные»
    models.py = «как данные хранятся и какие правила у сущностей»
    templates/ = «что пользователь увидит»
    static/*.css = «как выглядит»
    static/*.js = «как ведёт себя на клиенте»
    admin.py = «как этим управлять из /admin/»

4. ГЛАВНЫЙ ШАБЛОН И НАСЛЕДОВАНИЕ
------------------------------------------------------------

main/templates/main/base.html — главный layout сайта.
Он содержит:
- <head>;
- подключение style.css;
- верхнюю панель;
- логотип и телефон;
- кнопку «Каталог» и mega-menu;
- поиск;
- навигацию;
- мини-корзину;
- сообщения Django;
- <main id="main-content"> и block content;
- подключение общих JS: utils.js, cartModal.js, product-quantity.js,
  bannerSlider.js, catalogMenu.js, imageModal.js.

Дочерняя страница обычно делает так:

    {% extends 'main/base.html' %}
    {% block title %}...{% endblock %}
    {% block extra_css %}...{% endblock %}
    {% block content %}...{% endblock %}
    {% block extra_js %}...{% endblock %}

Поэтому, если один элемент появляется «на всех страницах», это почти всегда base.html
или context processor.

------------------------------------------------------------
5. CONTEXT PROCESSORS — ПОЧЕМУ ДАННЫЕ ЕСТЬ ВО ВСЕХ ШАБЛОНАХ
------------------------------------------------------------

В shop/settings.py подключены:
    basket.context_processors.basket
    main.context_processors.categories
    main.context_processors.catalog_menu
    wishlist.context_processors.wishlist

Из-за этого шаблоны автоматически получают:
    basket       -> объект корзины
    categories   -> простые категории + бренды
    catalog_tree -> полноценное дерево mega-menu каталога
    wishlist     -> объект избранного

Это важно: base.html сам не вызывает Python-код корзины или каталога.
Он просто использует переменные, которые ему подготовили context processors.

7. ДАННЫЕ КАТАЛОГА
------------------------------------------------------------

В main/models.py есть общий Product и конкретные типы:
    Smartphone
    Headphone
    Charger
    Cable
    PowerBank

Это наследование моделей Django. Product содержит общие поля (название, цена, бренд,
фото, скидка, наличие, группа и т.п.), а дочерняя модель хранит характеристики конкретного типа.

Category — пользовательские категории каталога. Они образуют дерево:
    основная категория
        -> подкатегории

MainCategory и SubCategory — proxy-модели для удобного разделения категорий в админке.
В БД это отдельные таблицы не создаёт.

ProductGroup — серия/линейка товара, например конкретная линейка модели.
Группа может быть связана с несколькими подкатегориями.

Бренд связан с товарами через Product.brand.

------------------------------------------------------------
8. СКИДКИ И АКЦИИ
------------------------------------------------------------

У товара есть обычная скидка Product.discount.

Дополнительно есть ProductPromotion:
    акция на бренд
    акция на категорию
    акция на группу
    акция на конкретный товар

Product.effective_discount_percent возвращает большую из обычной скидки и лучшей активной акции.

CartPromotion — отдельная акция на содержимое корзины:
    на всю корзину
    на самый дешёвый товар
    на самый дорогой товар
    на N-й товар

Важно:
    Banner — только визуальный баннер.
    Наличие активного Banner не создаёт скидку.

------------------------------------------------------------
9. БОНУСНАЯ СИСТЕМА — ГДЕ ИСКАТЬ
------------------------------------------------------------

Главный файл:
    users/services/bonuses.py

Единый источник правил:
    BonusService

Основные константы:
    1% бонусов за подходящую покупку
    срок бонусов за покупку — 12 месяцев
    подарок ко дню рождения — 1000 бонусов
    окно дня рождения — 7 дней до + день рождения + 7 дней после
    бонусами можно покрывать максимум 50% стоимости каждой единицы товара
    1 бонус = 1 грн

BonusConsumption связывает списание с конкретными начислениями.
Это нужно, чтобы можно было правильно учитывать срок годности бонусов и тратить сначала
те бонусы, которые истекут раньше.

10. КОМАНДЫ DJANGO
------------------------------------------------------------

Из корня проекта:

    python manage.py runserver
    python manage.py migrate
    python manage.py test

Каталог:
    python manage.py dump_catalog
    python manage.py load_catalog

Бонусы:
    python manage.py issue_birthday_bonuses
    python manage.py expire_bonuses
    python manage.py recalculate_bonus_balances

instruction.txt содержит рабочий сценарий для Render:
    1. изменить данные через /admin/
    2. python manage.py dump_catalog
    3. python manage.py test
    4. закоммитить main/fixtures/catalog_dump.json
    5. git push
